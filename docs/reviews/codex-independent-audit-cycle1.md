## Findings (highest value first)

1. **Make save data non-destructive** — *No-Fail / ADR-0002*
   - Unsupported version returns an empty save (`SaveSystem.ts:205`); corrupt JSON
     also starts empty (`SaveSystem.ts:225`); nested `progress` assumed by
     `TownMapProgress.ts:21` and `ProfileScene.ts:41`; one-click full reset in
     `ParentSettingsScene.ts:100`.
   - Fix: normalize full profile/progress shape on load, migrate known versions,
     preserve raw unknown/corrupt saves under a backup key, make reset
     hold-to-confirm with undo/backup.
   - Hard-to-reverse: **yes** (the ADR-0002 localStorage contract).

2. **Do not let Back/Exit lose mission progress** — *No-Fail*
   - A 6-year-old presses Back accidentally. Back returns to map immediately
     (`RecyclingRunScene.ts:82`, `HouseBuilderScene.ts:62`, `FireFixScene.ts:89`);
     progress recorded only on completion (`MissionCompleteScene.ts:32`).
   - Fix: replace Back with pause/confirm/resume, or checkpoint mission drafts and
     resume without penalty.
   - Hard-to-reverse: **yes** — missions as resumable state machines vs disposable
     scene sessions.

3. **Centralize mission lifecycle and cleanup** — *architecture (the main fork)*
   - `MissionScene` lifecycle is defined (`types.ts:28`) but unused; mission scenes
     are plain `Phaser.Scene` (`RecyclingRunScene.ts:19`); listeners registered in
     `create` (`FireFixScene.ts:92`) and the scene restarts during play (`:108`).
   - Fix: a shared mission runtime/adapter owning input binding, teardown,
     pause/resume, completion, checkpoint policy, and result validation.
   - Hard-to-reverse: **yes — the main foundation fork.**

4. **Close input parity gaps** — *accessibility*
   - PRD requires D-pad/left stick (`prd-v0.1.0.md:76`); `InputIntent` maps gamepad
     button indexes only (`InputIntent.ts:41`); pointer collapses to confirm (`:64`).
   - Fix: one input source polling gamepad axes with deadzones, normalized held
     movement, touch regions/drag, feeding the same intents to every scene.
   - Hard-to-reverse: moderate.

5. **Measure touch targets after scaling** — *mobile/accessibility*
   - Fixed 960×540 canvas with FIT scaling (`GameConfig.ts:19`); min target 52
     (`AccessibilityRules.ts:6`); Fire Fix uses 90×52 buttons (`FireFixScene.ts:83`).
     52 game px can shrink below child-friendly physical size on phones.
   - Fix: responsive mobile layouts + smoke tests asserting final *CSS-pixel* target
     size, not just game-world size.
   - Hard-to-reverse: moderate (touches the virtual-resolution/layout model).

6. **Escalate helper mode until completion** — *No-Fail*
   - Fire Fix helper assists only once (`helperAssists === 0`, `FireFix.ts:119`);
     House Builder wrong parts only add a text hint (`HouseBuilder.ts:80`).
   - Fix: shared helper-mode thresholds — highlight target, snap aim,
     auto-place/auto-spray after repeated misses, always keep one-star completion.
   - Hard-to-reverse: no ADR needed, but centralize before adding missions.

7. **Add browser-level flow tests** — *test rigor*
   - Pure logic tests (`RecyclingRun.test.ts:54`, `SaveSystem.test.ts:97`) don't
     prove navigation, refresh persistence, listener cleanup, scaled touch, or real
     gamepad. No browser runner (`package.json:18`); PRD calls for Playwright (`:281`).
   - Fix: one Playwright smoke path — create profile, complete all three missions,
     refresh, verify stars/stickers, plus mobile-landscape viewport checks.
   - Hard-to-reverse: low (but should follow the mission-runtime decision).

8. **Turn prototype feedback into toy delight** — *fun*
   - Celebration is static circles/stars (`MissionCompleteScene.ts:68`,
     `Celebration.ts:11`); assets are placeholder (`ASSET_BACKLOG.md:46`).
   - Fix: refine the first three missions with bounce/snap animations, silly map
     decorations, sticker-book viewing, gentle SFX behind mute, original art.
   - Hard-to-reverse: moderate once production art direction is chosen.

9. **Keep IP safety automated** — *IP-safety*
   - Runtime looks IP-safe (no Paw Patrol hits in `src`, `tests`, `public`); asset
     intake is the regression risk. ADR-0003 + asset policy require source/license.
   - Fix: a CI check scanning `src`, `public`, and imported assets for forbidden
     terms plus asset-ledger completeness.
   - Hard-to-reverse: low.

## The single architectural fork (Codex's pick)

> Choose whether missions remain independent Phaser scenes that restart and bind
> their own inputs, **or** the project gets a shared **mission runtime boundary**
> now. Codex recommends the shared runtime: "the only clean place to enforce
> No-Fail, pause/resume/checkpointing, input parity, listener cleanup, result
> persistence, and future test coverage without scattering child-safety rules
> across every mission."

This is the seed for the Cycle 1 `grill-with-docs --auto` ADR session.
